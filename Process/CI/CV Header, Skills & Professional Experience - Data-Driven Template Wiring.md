## 1. What is the problem or opportunity?

Opened as a side branch of `[[Fix CV Bullet Evidence Linking in the Career Graph]]`: while designing the
`cv_structure` data model (which table/field feeds which CV section), it became clear the real Word
template (`Group CVs/CV_Template.docx`, gitignored, per-machine) **did not exist anywhere findable** —
`templateExists()` had always returned `false`, so every CV ever generated by C6 had silently used the
plain programmatic fallback builder, never the owner's real 2-page template. On top of that, Header,
Skills, Education, Executive Education, and Languages were never wired to real data at all — only
Profile and the 11 Professional Experience slots were dynamic (per `lib/docx/template.ts`'s own comment:
"education and languages are the template's curated scaffold").

This CI is everything that came out of fixing that, beyond the original bullet-linking scope:

- A real `cv_structure` proposal (which table/field feeds which CV section) built and iterated with the
  owner directly.
- Two new schema fields (`education.summary`, `languages.displayLevel`) the owner asked for by name.
- The actual `CV_Template.docx` located (in the owner's Obsidian vault, not the repo), rebuilt with real
  `<<...>>` tags, and placed where the app expects it — the first time this code path has ever run for real.
- Full wiring of Header, Skills, Education, Executive Education, Languages, and Professional Experience
  position headers into `lib/pipeline/tailoring.ts`'s `templateSlotData`.
- Two real, previously-invisible production bugs found and fixed while verifying against a live lead,
  because this was the first time any of this code had actually executed end to end.

## 2. What was built

### 2.1 Schema

- `education.summary` — `jsonb text[]`, default `[]`. Multi-line, bullet-like sub-content per education
  entry (e.g. "Selected for Full scholarship by Inter-American Development Bank (IDB) Program."), distinct
  from `notes` (stays internal, never rendered). **Gated exactly like a Professional Experience bullet** —
  only rendered when the education row was cited as green/Keep evidence for that specific lead
  (`requirementTailoring.evidenceKind === 'Education'`, `evidenceRef === education.refCode`); the base
  qualification/institution/dates are hard-mapped and always shown, matching how Positions already work.
- `languages.displayLevel` — the CV-facing label ("Fluent", "Native"), distinct from the technical
  `cefrLevel` ("C1", "C2"). A stable per-language attribute, not something that varies per tailoring.
- `positions.cityCountry` — new column; city/country was never in the DB at all, only ever static template
  text, until Position headers needed it (§2.4).
- `education.type` was confirmed to **already** distinguish Education vs. Executive Education
  (`'Executive Education'` vs. `Degree`/`Masters`/`Postgraduate Coursework`) — no new `cv_section` field
  was needed, contrary to the original proposal.
- **Found, not caused, by this CI**: `profiles.languages_summary` was already dropped from `schema.ts` in
  an earlier session but never actually migrated off the live DB — a real, populated stray column
  (`"English C1 · German C1 · Portuguese C2 (native) · Spanish B2"`). Dropped in migration `0035` once its
  replacement (`languages.displayLevel`) existed; confirmed dead first (no code references it, since
  `schema.ts` hasn't declared it since before this CI).
- Migrations `0034` (education/languages) and `0035` (positions.cityCountry + the languages_summary drop)
  applied against the live DB.

### 2.2 `CV_Template.docx`

Real source located: `OneDrive - Nuno & Nine\Documents\Obsidian Vault\JobSearch Camunda\Group CVs\
CV_Template New.docx` — a fully-rendered reference CV, not a tagged template (no `<<...>>` tags existed
anywhere; `templateExists()` had never had anything to find). Rebuilt via direct `word/document.xml` XML
surgery (unzip → edit → rezip, per the docx skill's "editing an existing document" path — docx-js can't
open existing files) into a real docxtemplater source with:

- Header: `<<Name>>`, `<<JD Group Primary>>`/`<<JD Group Secondary>>` (the tagline — confirmed against the
  reference doc to be the lead's own B5 classification, **not** `profiles.headline`, which is only ever an
  internal seed for the C5 prompt), `<<Location>>`/`<<Relocation>>`/`<<Phone>>`/`<<Email>>`/`<<Citizenship>>`.
- `<<Profile>>` — unchanged, already dynamic.
- The 11 Professional Experience `CV_SLOTS` tags — unchanged, already dynamic, now for the first time
  actually rendering through the real template instead of the fallback.
- `<<Skills>>` — new (§2.3).
- `<<Education>>`/`<<Executive Education>>`/`<<Languages>>` — new, one flat tag per section (the template's
  literal-key parser has no real loop construct, so each is pre-joined multi-line text, same pattern the
  Professional Experience slots already use).
- `<<Position A/B/C/D Header>>` and `<<Position A/B/C/D Dates>>` — new (§2.4).

Formatting iterated with the owner against a real example CV as reference: position headers merged to one
line ("Title at Company, City, Country"), the "Role Overview:" heading removed (role-overview content, when
present, sits as plain text directly under the position header — genuinely empty with no visual gap when
there's nothing Kept for it), "Key Projects:" introduces each position's numbered projects (numbered
continuously 1–7 across the whole CV, not restarting per position), Education/Executive Education dates
moved to their own line in full month names, Languages rendered as a real "•" bulleted list.

Placed at `Group CVs/CV_Template.docx` in both the main working directory and this branch's worktree.
`.gitignore`'s blanket `*.docx` rule (part of the repo's "personal data never committed" policy) now carries
a named exception for this one file, on the owner's explicit instruction — it's the docxtemplater source
C6 reads at render time, and it still carries this owner's real position/company history and Skills
categories as static text, so it's tracked deliberately, not because it's been scrubbed of personal
content. Flagged as something to revisit before this app is ever multi-tenant (see
`[[Generalize CV_SLOTS Beyond a Single Profile]]`).

### 2.3 `lib/pipeline/tailoring.ts` — `templateSlotData`

- Header fields, JD Group Primary/Secondary (from the lead being tailored, not the profile), Education/
  Executive Education (Keep-gated summary, full-month dates on their own line), Languages (bulleted,
  `displayLevel` falling back to `cefrLevel`) — all new.
- **Skills**: wired from C4's already-computed `skillsModel` (previously only consumed by the unused
  programmatic-fallback `CvModel`) — the real template had never shown any Skills at all before this.
  Exposed a real, separate bug: one lead produced 67 skill names in a single line. Added a **display-layer
  cap of 24 items** as an explicit stopgap, on the owner's instruction, while the actual cause (why C4
  produced that many) is tracked separately and deliberately left open —
  see `[[C5 Skills Selection Produces Unreadable Overflow]]`.
- **Position headers** (§2.4): `<<Position A–D Header>>`/`<<Position A–D Dates>>` built from the real
  `positions` table (title, company, the new `cityCountry`, `startDate`/`endDate`) — the one part of
  Professional Experience that had stayed static template text even after the CV_SLOTS bullets went fully
  dynamic. E/F (Project Analyst, Trade Marketing Coordinator) aren't part of the rendered CV and weren't
  given tags. `cityCountry` and full-month `startDate`/`endDate` for A–D were backfilled from the owner's
  own confirmed-correct reference CV text, not guessed — confirmed safe first (only other reader of these
  fields, `career-graph-view-model.ts`'s `dateKey`, just regex-extracts a leading 4-digit year regardless of
  format).
- **C7 (ATS rating) now sees Education and Languages.** Previously its prompt only ever included Profile,
  Skills, and bullets — meaning it could (and did, on the record) mark "Fluency in German and English"
  unverified even when the CV's own Languages section already stated it. Confirmed fixed: the same lead's
  re-run went from *"No explicit Languages section... only inferred"* (score 55) to *"English (Fluent) and
  German (C1) both present"* (score 78, with a legitimately finer critique — C1 vs. native).

### 2.4 A real bug fix, not cosmetic

The Professional Experience bullet loop had **never deduplicated** before this CI, because this was the
first time it had ever run against production data (`templateExists()` was always `false` prior). The same
bulletBank evidence legitimately answers multiple JD requirements, so `requirement_tailoring` (one row per
requirement) can cite the same evidence several times — without dedup, one lead's A1/A2/A3 bullets repeated
3–7× each. Fixed with a `seenLines` set in `templateSlotData`'s CV_SLOTS loop, keyed on the resolved bullet
text.

### 2.5 A real data-quality finding, not yet acted on

Wiring Position D's real `company` field surfaced that it stores `"Banco do Brasil AG"`, but the owner's
own confirmed-correct reference CV shows `"Banco do Brasil"` (no "AG") for that Lisbon-based role — a
distinct legal entity from the Vienna "AG" subsidiary the other three positions are under. **Not corrected
in this CI** — flagged to the owner rather than silently changed, since it's a factual correction to
employment-history data, not a formatting choice.
